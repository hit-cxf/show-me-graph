## 1. 锚点与版本边界

用户已明确阅读 Qwen-Image-2.0 技术报告时，追查激活函数的定义与来源、理解 VAE 压缩率口径及对比表的相关工作，是项目的直接动机。本方案以技术报告为主锚点，同时保留官方仓库入口。

- 主锚点：[Qwen-Image-2.0 Technical Report](https://arxiv.org/abs/2605.10730)，固定版本 `2605.10730v1`，提交日期 2026-05-11。[固定版本全文](https://arxiv.org/html/2605.10730v1)
- 官方资料入口：[QwenLM/Qwen-Image](https://github.com/QwenLM/Qwen-Image)。核实时仓库 News 包含 2.0 发布记录，但顶栏 Tech Report 指向初代报告；不能直接把它登记为 2.0 报告。
- 初代单独登记：[Qwen-Image Technical Report](https://arxiv.org/abs/2508.02324)。同系列名称不构成同一论文版本的充分依据。

模型发布日、论文提交日、论文版本日、资料获取日分开记录。官方仓库存在，也不直接证明某一模型版本的权重或训练代码完整开放。

## 3. 第一轮要验证的任务

### T1：来源与版本消歧

给系统同时输入仓库链接、2.0 报告和初代报告。预期生成两个论文工作及各自资料，不把初代参数、图表或引用混入 2.0。引用旧版本的原文时，必须能打开旧版本文件。

### T2：抽取并自动入主图

从种子中抽取模型、关键组件和若干方法/结论。每个节点和关系保留依据、证据、核验状态；结构合法后自动显示，不要求用户逐条批准。对同一方法的不同提法，记录别名和消歧理由。

### T3：区分引用、使用与演进

对每条候选关系阅读具体上下文，分别判断是否只有引用、明确使用某方法、借鉴设计，或扩展一个版本。为每条判断绑定证据；拿不准时保留 AI 推断。专门加入一条仅为背景介绍的引用作为负例，检查是否产生伪继承。

### T4：保留结论条件

选择一项表格结果，记录数据集、指标方向、模型配置和评测条件。测试系统能否避免将局部比较压缩成“某系统全面优于另一系统”。若需要跨行、跨列或跨段解释，保留全部证据位置。

### T5：三维整体与横纵切面

选择 3–5 篇论文，顶部平面展示论文关系，每篇论文下方悬挂一张具有局部二维布局的技术关系图，包含模型、组件、使用的方法、结论及至少一个孤立知识点。显示至少一条跨切面技术关系。验证三维总览、顶部论文横切面、单篇技术纵切面和跨论文技术横切面之间的切换；不能用普通树的纵向展开代替。

共享方法多处出现时仍对应一个身份，实体级备注同步；不同论文中的角色和局部证据分别保留。技术横切面按语义选择相关对象，避免仅依赖几何高度导致漏项。

### T6：原文跳转与错误处理

分别选择普通段落、跨栏文本、公式邻近内容、表格结果。用户点击与 Agent 调用返回同一个 evidence_id 和同一版本原文。替换文件或故意破坏锚点后，应显示失效，不默默跳到相似文字。

### T7：全程由 Agent 维护

使用建议标签“条件编码器”“潜空间压缩”“训练与对齐”“少步生成”“文字渲染”，创建一个保存视图，增加备注，更正一条关系并导出。标签只是组织示例，后续按用户实际关注的问题调整；不能自动当作新的学术断言。

### T8：一个激活函数引出的阅读调研

从用户指认的原文术语开始，先按原文确认函数名称与拼写，再查询定义、最初或关键来源、当前论文的使用方式、作者给出的理由与适用条件。分别保存“原文明示原因”和“根据其他文献推测原因”。用户首先看到能回答问题的简洁解释，然后可展开证据与技术谱系。

不将口述中的不确定术语直接写成已确认实体。再次提问相同函数时，应复用已有定义、来源和解释，只补当前上下文的差异。

### T9：一个 VAE 对比表引出的阅读调研

从具体表格单元格和正文出发，核实“压缩率”在该文中的定义、输入/潜变量形状、通道数与比较口径；空间缩放、元素数量比和存储量不能仅凭同一个倍率词混为一谈。

随后沿表格列出的模型查找相关设计、压缩设置、观测效果与暴露的问题。事实性比较保留数据集、指标方向和评测条件；机制解释区分原文结论与 Agent 推断。新发现论文进入顶部图，定义与技术点进入相应切面，并能单独查看跨论文 VAE 关系图。

两项阅读测试先作为极速模式验收：围绕当前问题和必要前置知识查阅，记录已调查与未调查范围。调研模式已确定为极速/深度；具体资源预算按任务配置。

### T10：深度模式与模式衔接

对同一锚点启动深度调查，Agent 主动建立论文技术点清单并系统执行，覆盖定义、方法、组件、技术来源、主要对比结果与限制，不要求用户继续逐条提问。复用 T8/T9 的已有成果，按缺口补充重要参考文献和跨论文关系。

验收深度过程中的增量入图与查询、任务暂停/恢复，以及最终覆盖报告。故意触发预算不足时，必须显示未完成项并能够续跑；不得以停止运行或只列出调查计划作为完整调查完成。两种模式都保持原文证据和 AI 推断状态。

### T11：从 Zotero 开始

在测试文献库中选择目录，导入书目、标签、笔记和 PDF。检查重复导入、多目录归属、多附件及本地附件缺失。修改测试条目元数据或替换附件后，增量读取应保留人工图谱修正与旧证据快照。

删除/移出目录的测试仅操作测试库：本应用更新来源状态，保留已有知识。验证图谱可返回来源条目，GUI 与 Agent 使用同一接口；未启用回写时，不向 Zotero 写入标签、笔记或新文献。

### T12：自动收录到指定目录

在测试文献库配置收录目标，分别运行极速和深度调研，验证新纳入论文自动进入指定目录，已有条目只增加目录归属并保留原分类；重复执行、模拟写入成功但响应丢失后重试都不得重复建条目。

覆盖仅有元数据、可用 PDF、附件补充失败、同名目录位于不同库、目录被删除及无写权限等样例。分别检查书目与附件状态；失败保存可重试队列，不默默改投其他目录。完整配置后不逐篇请求确认。测试不扩大为标签、笔记或删除操作的双向同步。

## 4. 试点产物与完成条件

1. 固定种子清单：论文 ID、版本、来源 URL、文件哈希及获取结果。
2. 图谱样本：规范实体、关系、证据及状态；同一实体跨论文复用。
3. 小型人工评估集：关键关系与原文锚点，含引用/继承混淆反例。
4. 四种可恢复视图：三维整体、论文横切面、指定论文技术纵切面、跨论文 VAE 技术横切面；一个可恢复归档。
5. 开源底座比较：同样本、同测试问题的运行记录与采用建议。
6. 失败清单：缺全文、错误消歧、锚点失效、关系误判、上下文遗漏及解析不支持项。
7. 两项带证据的阅读问题解释及其新增知识；相关问题复用测试记录。
8. 深度调查清单与覆盖报告、两种模式共享成果及中断续跑的测试记录。
9. Zotero 来源映射、增量读取、异常附件与原文快照测试记录。
10. 指定目录自动收录、去重、部分失败及重试记录。

M0 以是否能够完成这些操作并识别主要缺口为目标；正式精度、定位与接口覆盖门槛在 M5 按主任务书验收。初期不追求穷尽图像生成领域，也不将这份候选清单当作已经完成的研究综述。
