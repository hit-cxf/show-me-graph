## 现在可以打开什么

本机运行地址：[Show Me Graph M0](http://127.0.0.1:4317)。服务只监听回环地址；`npm start` 已改为独立后台启动，避免依赖临时执行会话。用 `npm run status` 查询、`npm stop` 停止；电脑重启后按下方命令重启服务。

1. 默认选择 Qwen-Image-2.0、SD3、DC-AE，观察顶部论文图及三张下悬技术切面。
2. 点击论文标题，进入对应技术纵切面；也可用顶部按钮查看其他切面。
3. 右侧下拉选择 `SwiGLU`、`Qwen-Image-2.0 VAE` 或某条关系，查看引文、页码、指纹与高亮。
4. 选择 `Qwen-Image-2.0 Distillation`，对照同页图注与正文的教师身份冲突。
5. 勾选更多论文，观察共享实体的跨切面出现位置。虚线中的身份/所属连接是视图连接，不能解释为科学继承。

图的长标签仍可能重叠，缩放或使用单篇切面及选择器阅读；这是布局优化的已知问题。当前只读API覆盖样本获取与证据解析，没有持久化编辑/保存视图接口，不能宣称已达到人机操作全面等价。

2026-10-05 根据用户反馈更新：论文顶层以引用分叉排列，保留多父和跨分支关系；技术切面转为侧向纵深排列。左右栏支持默认/展开两档，右侧PDF随宽度放大；增加默认明亮与可记忆的夜间模式。Chrome验证了两侧展开/恢复、PDF放大后高亮、主题刷新保持，以及1024/780/390px窗口下无横向溢出。全套既有证据与四视图检查仍通过。

## 语料与可信性边界

- [manifest.json](../experiments/corpus/manifest.json)：10篇的固定版本、下载URL、哈希、状态及页数；所有论文都是固定v1，不宣称最新。
- [propositions.json](../experiments/corpus/propositions.json)：Agent阅读后精选的语义样本，**不是整篇自动抽取结果**。关系准确率没有独立人工金标准评测。
- [evidence.json](../experiments/corpus/evidence.json)：引文、PDF从1起算的页码、左上原点的逐行矩形、文件哈希、定位与视觉检查状态。
- [validation.json](../experiments/corpus/validation.json)：30个正例及四类破坏负例的实际校验结果。
- API每次解析证据对比该版本文件哈希；PDF缓存按论文ID和哈希隔离。显示“定位通过”不等于关系解释已被用户复核。
- 当前样本同一关系的实体端点在最多一个共同论文上下文中同时出现。M1必须给断言增加明确的出现位置/作用域；不能把某论文中的关系复制到所有含同名实体的切面。

真实阅读暴露了几个必要设计：`SwiGLU`需要术语消歧；`f16c64`的16是空间维缩小，不能误叫文件体积压缩率；VAE表格需要保留指标与数据集；MeanFlow背景引用不能升级成“采用”；教师Base/RL表述冲突要并列保留。具体引文与条件见证据报告，未把这些样本扩写成完整综述。

## 复现

已有语料与JSON时，运行原型：

```sh
cd experiments/prototype
npm ci
npm run build
npm start
```

另一个终端执行 `npm run check`。默认使用本机 `/Applications/Google Chrome.app/Contents/MacOS/Google Chrome`，其他环境用 `SMG_BROWSER` 指定实际浏览器可执行文件。检查包含真实浏览器视图切换、节点/关系证据、页码/高亮、筛选和API失败路径；不会写Zotero。

PDF未纳入版本控制。重新获取语料与证据：在项目根目录用安装了PyMuPDF的Python运行 `experiments/scripts/evidence-download.py`、必要时运行 `evidence-retry.py`，再运行证据报告中列出的抽取/校验脚本。视觉复核是实际执行记录，不能仅重新生成JSON就声称已经复核新文件。下载依赖当时arXiv网络可用性，哈希变化必须重新调查。

只读接口：

| GET路径 | 输出 |
| --- | --- |
| `/api/health` | M0/read-only状态 |
| `/api/manifest` | 版本化语料清单 |
| `/api/graph` | 精选实体、关系及冲突 |
| `/api/evidence` | 证据索引 |
| `/api/evidence/:id` | 版本哈希校验后原文、坐标和文件入口 |
| `/api/artifacts/:paper_id/file` | 仅允许清单内且哈希匹配的PDF |

## 尚未满足的 M0 退出条件

1. 用户指定实际 Zotero 目录后，验证复用既有条目、收录新条目、附件补全、重复执行与失败重试。官方本地写授权可能另弹客户端对话框；当前没有申请或保存密钥。
2. GROBID/Docling尚未实跑，M0用PyMuPDF定位、用sift的pdfplumber读文本。不能据此冻结正式结构解析器。
3. google-surf-mcp仅做过文档调研，未运行；两个主要候选也没有完成同批10篇的自动语义抽取横向准确率比较。
4. 深度/极速任务、SQLite规范库、修订/幂等、Skill、备注标签分组、完整操作API、跨Agent宿主兼容性还在后续阶段。

下一阶段应先冻结数据契约与证据失效行为，再做可维护的主库；同时补齐上述M0测试。原型代码可用于验证布局和阅读，不应不加区分地成为生产数据架构。
